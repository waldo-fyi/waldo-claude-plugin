## How to run

In a fresh terminal (separate from any active Claude Code session):

```bash
cd /path/to/waldo-agentic
git checkout main
claude --plugin-dir packages/waldo-claude-plugins/plugins/waldo-strategy
```

For each prompt below:

1. Paste the prompt verbatim into the fresh Claude Code session.
2. Observe which Waldo skill (if any) Claude invokes. The skill name appears in the tool-use trail or system-reminder; you can also ask Claude "which skill did you use?" if it isn't obvious.
3. Score routing per the rubric.
4. Score answer quality 1 / 3 / 5 per each prompt's rubric (printed inline below).
5. Fill in the v0.2 measurement column.
6. Move to the next prompt in the SAME session (multi-turn) OR start a fresh session per prompt — note which approach you used in the metadata above.

**Routing rubric** (from `evals/README.md`):

- **Pass** — Primary skill (first in `expected_skills`) fires. No wrong skills fire. For `expected_skills: []`, no Waldo skill fires.
- **Partial** — Primary fires alongside a wrong skill, OR only a complementary skill fires.
- **Fail** — Wrong skill fires, no skill fires when one was expected, or any skill fires when none was expected.

**Target lift:** ≥30 percentage-point increase on routing pass rate vs the v0.1 baseline (5/7 = 71.4% → ≥85.7% on the smoke set; ≥30 pp on the full 34 set once measured).

**Decision after smoke test:** **Proceed to the remaining 27 prompts.** Smoke pass rate hit the ≥85.7% absolute threshold exactly (6/7). The +14.3 pp lift is below the originally-stated 30 pp target, but the absolute threshold is met and the lift direction is correct. **Persona case fixed cleanly** — `persona-02` flipped Fail → Pass, quality 3 → 5 — the most encouraging signal that Saurav's tuning plus the new MCP "When to Use Waldo" preamble are working as designed for grounded persona simulations. **Strategic-POV case did not budge** — `strategic-pov-01` produced the identical Fail / quality-3 result as v0.1. Watch `strategic-pov-02` in the remaining set to see if this is prompt-specific or POV-pattern-wide; if POV-pattern-wide, that's a v0.2.1 description-tuning iteration target, not a Stage 1 blocker.

### Secondary observations from smoke test (v0.2)

- **Complementary skills still don't auto-load.** Same as v0.1 — Claude treats most prompts as single-skill tasks (see notes on `consumer-trends-01`, `competitive-02`, `influencer-02`). Description tuning did not change this; complementary co-fire remains a quality observation, not a routing requirement. Eval rubric is forgiving here — all Pass cases scored quality 5.
- **Slash commands surfacing in the auto-routing trail.** `persona-02`, `cultural-social-01`, and `competitive-02` show the slash command (`deep-dive`, `social-listening`) appearing alongside the underlying skill in the tool trail, even though the prompts were typed in natural language. Most likely interpretation: Pattern A-prime's slash-command-as-skill-loader architecture means the trail records both the command name and the skill it loaded — single logical action, not two skills firing. Cherilyn's notes corroborate: "when asked, it said web-research was loaded" → confirms the slash command is a load mechanism, not a co-fired skill. Worth a separate confirmation with Anthropic on whether the trail format is documented behavior, since reviewers may misread it as two skills firing.
- **Brief clarification still skipped** in `cultural-social-01` and `influencer-02` despite the `social-intelligence` SKILL.md body asking for it. Same as v0.1 — this is a SKILL.md body issue, not gated by description tuning. Tracked as a v0.3 polish item separate from this card.
- **"When the data isn't there" methodology not exercised in smoke.** None of the 7 prompts hit a tool-error / empty-result / wrong-entity scenario, so the new section had nothing to react to. Watch the remaining 27 — most likely surface point is `account-*`, `datapoints-01`, or any social prompt where Vetric returns nothing.
- **No over-fires observed.** `Do NOT trigger` clauses appear to be holding — no wrong skill fired alongside primary on any Pass case, and the negative test (`negative-04`) cleanly suppressed all skill loads with Claude using internal knowledge as expected.
- **Quality lift is real and concentrated on the persona unlock.** Average jumped 4.33 → 4.67 driven entirely by `persona-02` flipping. Once `strategic-pov-01` is addressed, average quality will climb further (the single remaining quality-3 row is that one prompt).

## Stage 1 conclusions and follow-on actions

### Headline numbers

- **Routing pass rate: 67.6% (23/34)** across the full set; **85.7% (6/7) on the smoke** — the smoke threshold for launch readiness was met
- **Average answer quality: 4.86 / 5** across 28 scored prompts. 26 of 28 scored 5; only `strategic-pov-01` and `desk-research-04` scored 3
- **Negative tests: 5/5 clean** (plus the smoke `negative-04`) — no false-positive skill firing on any should-not-trigger prompt
- **Smoke 7 lift vs v0.1: +14.3 pp** on routing pass rate (71.4% → 85.7%), +0.34 on average quality (4.33 → 4.67)

### Routing vs quality were scored independently

Routing measures whether the *right skill loads on the first turn*. Quality measures whether the *final answer is good* — including conversation correction. This decoupling is important for reading the numbers honestly.

Rebreaking the 9 routing Fails:

| Type | Count | Prompts | What happened |
|---|---|---|---|
| True fail (no skill ever fired) | 2 | `strategic-pov-01`, `persona-01` | Claude answered from training; even after follow-up, no skill loaded |
| Multi-turn recovery (skill fired after user reframed) | 7 | `creative-brief-02`, `desk-research-04`, `competitive-01`, `influencer-01`, `influencer-03`, `ai-innovation-01`, `ai-innovation-02` | Initial response was internal-knowledge or clarifying-question; right skill loaded after user nudged |

Recasting:
- **True clean Pass: 23/34 (67.6%)**
- **Pass with multi-turn recovery: +7/34 (20.6%)** → effective Pass-or-Recovered: **30/34 (88.2%)**
- **Partial: 2/34 (5.9%)**
- **True Fail (no skill ever fired): 2/34 (5.9%)**

The conversation-level success rate (88.2%) is materially better than the strict first-turn pass rate (67.6%). For end-user experience, the relevant question is whether multi-turn recovery is acceptable or whether we want stronger first-turn loading.

### Skill-coverage gap in the eval set

The 28 should-trigger prompts are heavily weighted toward `web-research`:

- `web-research` expected (any role) in 25 of 28 prompts (89%)
- `social-intelligence` expected in 12 of 28 (43%)
- `ad-intelligence` expected in only 3 of 28 (11%)
- `archival-knowledge` expected in 0 of 28
- `data-analysis` expected in 0 of 28

The eval validates `web-research` thoroughly, gives partial coverage of `social-intelligence`, and provides almost no coverage of `ad-intelligence`, `archival-knowledge`, or `data-analysis`. **Stage 2 testing should supplement with prompts that exercise these three under-tested skills.** The `archival-knowledge` non-fire on `persona-01` (#12, when explicit "Waldo workspace" framing was added in conversation) is a meaningful signal precisely because nothing else in the eval set tests that skill.

### Observations from the testing process (prompts 17–34)

- **No two skills loaded in parallel or sequentially in any test.** Single-skill firing was the norm even on prompts where complementary skills were expected (e.g. `competitive-02` with `web-research + ad-intelligence`, `ai-innovation-01` with `web-research + ad-intelligence`). The complementary-as-quality-bonus design holds, but auto-loading a second skill never happened. The closest case was `datapoints-01` (#29) where `data-analysis` loaded after the user explicitly asked for analysis on the returned data — multi-turn, not parallel.
- **Brief clarification still skipped consistently** on `social-intelligence`-led prompts (timeframe, platforms, brand/topic/category not checked before tool calls). Same SKILL.md body issue surfaced on every social-intelligence prompt. v0.3 polish item already queued.
- **Speed: `ad-intelligence` is slow in Claude CLI.** Python scripts process the ad results, write temp files, parse output before the response generates. End-user perceived latency could be material. **Unknown whether this slowness reproduces on Claude Code (web) or Cowork** — worth measuring during Stage 2.
- **Internal-knowledge fallback without skill loading is the dominant Fail mode.** 7 of 9 routing Fails involve Claude answering from training first, then loading a skill only when the user nudges. Some form of guardrail to prevent silent training-only responses (or at minimum a disclosure that no skill ran) would tighten the experience and reduce the trust-decay risk @saurav flagged in [PRO-2348](https://linear.app/waldofyi/issue/PRO-2348) §3.4.
- **`desk-research-02` (#16) routing-expectation may need review.** Expected primary `web-research`; the prompt ("cultural conversation around work-life balance shifting in 2025") reads more like a `social-intelligence` first-call. Possible eval-harness refinement: flip the `expected_skills` order for this entry.
